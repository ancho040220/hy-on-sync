# 노션 과제DB → 구글 캘린더 미러 설계 (2026-11-21)

## 의도

노션 과제DB의 과제·퀴즈는 노션 캘린더 앱에서만 보인다. 노션 캘린더는 DB 항목을 구글 캘린더에 실제 일정으로 쓰지 않기 때문이다. 사용자는 휴대폰(삼성 캘린더)이나 구글 캘린더에서도 이번 학기 과제를 한눈에 보고 싶어 한다. 지난 과제까지 포함한 '학기 정리' 화면도 원한다.

## 목표 / 비목표 / 실패 기준

- **목표:** 동기화가 돌 때마다(하루 3번) 노션 과제DB를 구글 캘린더의 **전용 캘린더**에 그대로 비춘다. 노션 캘린더에서 보는 화면과 같아야 한다.
- **비목표:** 구글에서 고친 내용을 노션에 반영하는 것(단방향만). 시험과 동영상을 이 캘린더에 올리는 것(시험은 사용자가 이미 기본 캘린더에 직접 넣는다). 일정 알림(구글 알림)을 설정하는 것.
- **실패 기준:** 사용자의 기본 캘린더나 다른 캘린더의 일정을 건드리면 실패다. 실행할 때마다 일정이 중복으로 쌓여도 실패다. 구글 쪽 오류 때문에 카톡이나 노션 쓰기가 막혀도 실패다.

## 제약

- Python 3.12(Actions) / 3.11(로컬). HTTP는 `httpx`로 직접 호출한다(기존 노션·카카오 클라이언트와 같은 방식).
- 알림·동기화 규칙은 `planner.py`에만 둔다. 규칙은 `tests/test_planner.py`에 테스트부터 추가한다.
- 외부 서비스에 처음 연결할 때는 `--dry-run`으로 먼저 확인한다.
- `.env`는 사용자가 채운다. 비밀값은 출력하지 않는다.
- 사용자는 주 5시간 이하로 작업한다. 이 작업 다음에 6단계(GitHub·Actions, 12/6 목표)가 있다.

## 접근 (검토한 것과 결정)

| 안 | 내용 | 장단점 |
| --- | --- | --- |
| **A. 스크립트가 구글 캘린더 API로 직접 쓰기 (선택)** | 서비스 계정으로 전용 캘린더에 일정을 만들고, 고치고, 지운다 | 실행마다 바로 반영되고 무료다. 코드와 구글 클라우드 설정이 필요하다 |
| B. iCal 파일을 만들어 구글에서 구독 | 스크립트가 `.ics`를 만들어 공개 주소에 올린다 | 구글이 12~24시간마다만 갱신한다. 공개 주소가 필요하다 |
| C. Make·Zapier 같은 외부 자동화 | 노코드 템플릿 | 노션·구글 권한을 서비스가 하나 더 갖는다. 무료 한도와 정책 변경에 묶인다 |

사용자가 A를 골랐다. 프로젝트 안에서 관리할 수 있고, 반영이 바로 되기 때문이다. 인증은 **서비스 계정**으로 한다. 개인 OAuth 토큰은 테스트 상태의 구글 앱에서 7일마다 만료되는 것으로 알려져 있어서 무인 실행에 맞지 않는다.

## 사용자가 정한 것

1. **노션 DB를 그대로 올린다.** 날짜가 있는 노션 레코드는 지난 과제와 완료한 과제까지 모두 올린다. 노션에서 지운 항목은 구글에서도 지운다(스크립트가 만든 일정만).
2. **완료 표시:** 진행 상태가 '완료'면 일정 제목 앞에 `✓ `를 붙인다.
3. **모양:** 노션처럼 시작일~마감 막대로 그린다(막대가 많아도 괜찮다고 했다).
4. A안 다음에 6단계를 진행한다.

## 동작

**실행 순서:** 읽기 → 계획 → 카톡 → 노션 쓰기 → **구글 미러** → 상태 저장.

1. 노션 쓰기가 끝나면 노션 레코드를 다시 읽는다(`NotionStore.query_all()`).
2. 전용 캘린더의 일정을 모두 읽는다. 지운 일정도 포함한다(`showDeleted=true`).
3. 순수 함수 `plan_gcal(records, events)`가 만들 것·고칠 것·지울 것을 정한다(`planner.py`).
4. 구글에 반영한다.

**일정 하나의 모양**
- 일정 ID: 노션 `page_id`에서 `-`를 뺀 32자리 16진수를 그대로 쓴다. 구글 일정 ID에 허용되는 문자(소문자 a–v, 0–9)에 들어가므로, 같은 레코드는 언제나 같은 일정이 된다. 이 방식으로 중복을 막는다.
- 제목: `{과목} · {과제명}`, 완료면 `✓ {과목} · {과제명}`. 과목이 없으면 과제명만 쓴다.
- 시간: 시작 = 레코드 `start`, 끝 = 레코드 `end`. 시간대는 Asia/Seoul.
- 설명: HY-ON 링크(`url`)가 있으면 넣는다.
- 날짜가 없는 레코드는 올리지 않는다(스크립트가 만든 일정이 있었으면 지운다).

**비교 규칙 (`plan_gcal`)**
- 레코드는 있는데 일정이 없음 → 만든다.
- 레코드도 있고 일정도 있는데 제목·시간·설명이 다름 → 고친다.
- 일정이 '지워짐(cancelled)' 상태로 남아 있음 → 같은 ID로 새로 만들 수 없으므로(구글이 409를 돌려줌) 상태를 되살리면서 고친다.
- 일정은 있는데 대응하는 레코드가 없음 → **스크립트가 만든 일정(`extendedProperties.private.hysync = "mirror"` 표시)만** 지운다. 표시 없는 일정은 건드리지 않는다. 캘린더 ID를 잘못 넣어 개인 캘린더를 가리켜도 수업·알바 일정을 지우지 않기 위해서다(실패 기준 1을 코드로 지킴). *(2026-11-21 최종 점검에서 추가)*
- 아무것도 다르지 않음 → 아무것도 하지 않는다(API 호출을 줄인다).

**오류 처리**
- 구글 쪽 오류(인증 실패, 권한 없음 등)는 미러 단계 안에서 잡아 로그로 남긴다. **상태 파일 저장과 카카오 리프레시 토큰 파일 쓰기는 그대로 한다.** 그렇지 않으면 다음 실행 때 시험·동영상 카톡이 다시 가고, 새 카카오 토큰이 워크플로에 넘어가지 않는다. 실행 결과만 실패(종료 코드 1)로 끝내서 GitHub가 메일로 알려 주게 한다(`Result`에 구글용 성공 여부를 하나 더 둔다). 다음 실행에서 처음부터 다시 비교하므로 저절로 복구된다. *(Claude가 정함, 실패 기준에 따름)*
- 같은 ID로 일정을 만들다가 409가 나면, 같은 ID로 고치면서 상태를 되살린다. 구글은 지운 일정 ID를 지운 목록에서 사라진 뒤에도 잡아 두기 때문이다. *(Claude가 정함)*
- 설정이 비어 있으면(`GCAL_TARGET_CALENDAR_ID`가 없거나 키 파일이 없음) 미러를 건너뛴다. 지금처럼 동작한다. Actions에서는 키 Secret이 비어 있으면 파일을 만들지 않는다. *(Claude가 정함)*

**dry-run**
- 구글 캘린더를 읽기만 하고, 만들 것·고칠 것·지울 것의 개수와 목록을 출력한다. 노션을 쓰지 않으므로 쓰기 전 노션 레코드를 기준으로 비교한다. *(Claude가 정함)*
- 실제 실행에서 노션에 쓴 게 없으면 노션을 다시 읽지 않고 처음 읽은 레코드를 쓴다. *(Claude가 정함)*

## 설정

| 이름 | 값 | 비고 |
| --- | --- | --- |
| `GCAL_TARGET_CALENDAR_ID` | 전용 캘린더 ID (`...@group.calendar.google.com`) | 비밀값은 아니지만 Secret으로 둔다 |
| `GCAL_SERVICE_ACCOUNT_FILE` | 서비스 계정 키 JSON 파일 경로 | 로컬 기본값 `gcal-service-account.json`(프로젝트 폴더, `.gitignore`) |
| (Actions) `GCAL_SERVICE_ACCOUNT_JSON` Secret | 키 JSON 내용 | 워크플로가 실행 전에 파일로 쓰고 경로를 넘긴다 |

**사용자가 할 준비** (README와 HANDOFF에 단계별로 적는다)
1. 구글 클라우드 콘솔에서 프로젝트를 만들고 Google Calendar API를 켠다.
2. 서비스 계정을 만들고 JSON 키를 받아 프로젝트 폴더에 `gcal-service-account.json`으로 둔다.
3. 구글 캘린더에서 새 캘린더 'HY-ON 과제'를 만든다. 서비스 계정 이메일에 **'일정 변경'** 권한으로 공유한다.
4. 그 캘린더의 ID를 `.env`의 `GCAL_TARGET_CALENDAR_ID`에 넣는다.
5. 색은 구글 캘린더에서 이 캘린더의 색을 바꾸면 된다.
6. 노션 캘린더 앱에서는 같은 과제가 두 번 보이게 된다(노션 DB 하나, 'HY-ON 과제' 캘린더 하나). 노션 캘린더에서는 'HY-ON 과제' 캘린더를 숨긴다. *(Claude가 정함)*

이 캘린더는 시험 읽기에 쓰는 것과 같은 **개인 Gmail 계정**에 만든다. 학교 Workspace 계정은 외부 주소(서비스 계정)와의 공유를 막을 수 있다. *(Claude가 정함, HANDOFF 기록에 근거)*

## 인증

- 서비스 계정 키로 JWT(RS256)를 서명해 `https://oauth2.googleapis.com/token`에서 액세스 토큰을 받는다. 범위는 `https://www.googleapis.com/auth/calendar.events`.
- 서명에는 `pyjwt[crypto]`를 쓴다. 지금은 `mcp`에 딸려 설치되지만, 기본 의존성에 직접 추가한다(Actions는 `pip install .`만 한다).

## 빌더에게 맡기는 것

- 모듈 이름과 구조(예: `gcal_writer.py`에 클라이언트를 두고, `plan_gcal`은 `planner.py`).
- 액세스 토큰을 실행 중에 재사용할지(한 번 실행에 토큰 하나면 충분하다).
- 날짜만 있는 레코드(손으로 넣은 항목, 시각이 없음)를 종일 일정으로 그릴지. 지금 DB에는 이런 레코드가 없다.
- 구글 API 페이지 넘김과 일시적 오류(429/5xx) 재시도 정도.
- 테스트는 기존처럼 가짜 응답(`httpx.MockTransport`)으로 쓴다.
