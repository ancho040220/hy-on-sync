# HY-ON × 노션 과제 플래너 자동 연동 프로젝트 계획서

2026-11-21 기준. 원본은 claude.ai 문서이며, 이 파일은 Claude Code가 읽을 수 있게 옮긴 사본이다. 구조도와 일정표는 그림 대신 글로 바꿨다.

## 개요

HY-ON(학교 LMS)에 올라온 과제를 노션 과제 플래너에 자동으로 등록하고, 마감이 다가오면 카카오톡으로 알려주는 개인 자동화 도구다.

**배경.** 노션 과제DB는 이미 노션 캘린더를 거쳐 구글 캘린더까지 이어져 있다. 남은 수동 단계는 LMS 과제를 확인해 노션에 옮겨 적는 일 하나다. 이 단계만 자동화하면 LMS에서 캘린더까지 흐름 전체가 손 없이 돌아간다.

**목표**

- LMS에 공개된 과제가 정해진 주기마다 노션 과제DB에 자동으로 등록된다.
- 각 과제는 시작일(공개일, 없으면 마감일에서 역산)부터 제출일까지 기간으로 들어간다.
- 새 과제와 마감 임박 과제를 카카오톡 나에게 보내기로 알린다.
- (2단계) LMS를 MCP 서버로 감싸, Claude에게 과제를 묻고 정리를 맡길 수 있게 한다.

개인용이자 포트폴리오용이라, 무엇을 만드는지와 함께 그렇게 정한 이유도 기록한다.

## 범위

이번 학기 기말 전까지 두 단계를 모두 끝낸다. 1단계는 동기화와 알림, 2단계는 그 위에 얹는 MCP 서버다.

| 구분 | 1단계: 동기화 + 알림 | 2단계: LMS MCP 서버 |
| --- | --- | --- |
| 목표 시점 | 이번 학기 기말 전 | 이번 학기 기말 전 (1단계 직후) |
| 노션 과제DB에 등록 | 과제, 퀴즈 | (1단계 결과를 그대로 씀) |
| 카카오톡 알림 | 과제·퀴즈(새 항목, 마감 임박, 변경), 시험(구글 캘린더), 동영상 강의 출석 기한 | — |
| 하는 일 | LMS·구글 캘린더 조회 → 노션 등록·갱신 → 알림 발송 | Claude에서 과제 조회, 공지 요약, 주간 계획 |
| 실행 위치 | GitHub Actions 정기 실행 | 내 PC의 로컬 MCP 서버 |

동영상 강의는 노션에 넣지 않고 카카오톡으로만 알린다. 강의마다 항목이 쌓이면 과제 플래너가 금방 복잡해지기 때문이다. 시험은 보통 따로 공지되므로 LMS에서 가져오지 않는다. 내가 구글 캘린더에 직접 등록한 시험 일정을 읽어 카카오톡으로만 알린다.

**이번에 하지 않는 것**

- 공지사항 수집 (2단계 MCP에서 조회만 검토)
- 과제 제출 자동화, 노션에서 LMS로의 역방향 동기화
- 다른 학생이 쓸 수 있는 서비스화 (내 계정 전용)

## 시스템 구조

동기화 스크립트 하나가 LMS와 구글 캘린더(시험)를 읽어 노션과 카카오톡에 나눠 보내고, 캘린더는 기존 노션 연동을 그대로 탄다.

```
[1단계 · 자동 동기화]
HY-ON (Canvas: 과제·퀴즈, 동영상 강의 기한) --Canvas API--> 동기화 스크립트 (GitHub Actions, 하루 3번)
구글 캘린더 (시험 일정, 내가 직접 등록) --iCal--> 동기화 스크립트
동기화 스크립트 --알림--> 카카오톡 (신규 · D-3 · D-1 · 변경)
동기화 스크립트 --등록·갱신--> 노션 과제DB (과제·퀴즈) --노션 캘린더 경유(기존)--> 구글 캘린더

[2단계 · 대화형 레이어]
Claude (데스크톱 · Claude Code) --> LMS MCP 서버 --조회--> HY-ON
Claude --> 노션 MCP (기존 연결) --쓰기--> 노션 과제DB
```

1단계는 사람이 손대지 않아도 하루 3번 돈다. 2단계는 내가 Claude에게 물을 때만 LMS를 조회하고, 노션에 쓰는 일은 기존 노션 MCP가 맡는다.

## 데이터 설계

기존 과제DB는 그대로 쓰고 속성 4개만 추가한다. 스크립트는 LMS에서 온 값만 고치고, 진행 상태와 메모는 건드리지 않는다.

| 노션 속성 | 종류 | 채우는 값 | 스크립트가 수정 |
| --- | --- | --- | --- |
| 과제명 | 제목 (기존) | LMS 항목 이름 | 예 |
| 과목 | 선택 (기존) | LMS 강의명. 없는 과목은 선택지로 자동 추가 | 예 |
| 마감 날짜 | 날짜 범위 (기존) | 시작 = 공개일(없으면 마감 7일 전), 끝 = 마감 일시(KST) | 예 |
| 진행 상태 | 상태 (기존) | 새 항목에만 '시작 전' | 아니오 |
| 메모 | 텍스트 (기존) | — | 아니오 |
| 유형 | 선택 (추가) | 과제 / 퀴즈 | 예 |
| LMS ID | 텍스트 (추가) | 유형 + LMS 고유번호 (예: assignment-1234-56789, 강의 ID와 과제 ID) | 처음 한 번 |
| 링크 | URL (추가) | LMS 항목 페이지 주소 | 예 |
| 알림 기록 | 다중 선택 (추가) | 보낸 알림: 신규 / D-3 / D-1 | 예 |

**동기화 규칙**

1. LMS ID로 노션을 찾아 없으면 새로 만들고, 있으면 바뀐 값만 갱신한다.
2. 마감일이 바뀌면 날짜를 LMS 기준으로 덮어쓰고 카카오톡으로 알린다. 알림 기록의 D-3, D-1은 지워 새 마감에 맞춰 다시 보내게 한다.
3. 마감일이 없거나 이미 지난 항목은 새로 등록하지 않는다. (2026-11-21 변경: 처음에는 날짜를 비워 등록하기로 했지만, 실제 HY-ON에 마감 없는 성적 칸과 지난 과제가 많아 첫 실행 때 불필요한 항목과 알림이 쏟아지는 것을 막으려고 바꿨다.)
4. LMS에서 사라진 항목은 노션에서 지우지 않는다.
5. 첫 실행 때는 LMS ID 없이 손으로 넣어둔 항목과 과목·과제명이 같으면 새로 만들지 않고 LMS ID만 채워 연결한다.

알림 기록을 노션에 두는 이유: GitHub Actions는 실행이 끝나면 상태가 사라지는데, 하루 3번 도는 동안 같은 D-1 알림을 세 번 보내면 안 된다. 별도 DB 없이 중복 발송을 막는 가장 단순한 방법이다.

**LMS에서 가져올 값 (후보)**

HY-ON은 Canvas 기반이라 Canvas REST API를 기준으로 잡는다. 실제로 열려 있는지는 1주 차에 확인한다.

- 과제: 강의별 과제 목록 (`unlock_at` 공개일, `due_at` 마감, `html_url` 링크)
- 퀴즈: 강의별 퀴즈 목록 (같은 필드)
- 시험: LMS에서 가져오지 않는다. 구글 캘린더의 비공개 iCal 주소를 읽어 제목에 '시험'이나 '고사'가 들어간 일정만 골라 알림에 쓴다.
- 동영상 강의: LearningX 쪽 데이터라 Canvas API로 보이는지 확인이 필요하다.

## 알림 설계

알림은 카카오톡 나에게 보내기 하나로만 보낸다. 캘린더 쪽은 이미 노션 → 노션 캘린더 → 구글 캘린더로 이어져 있어서 따로 만들지 않는다.

| 시점 | 대상 | 메시지 예시 |
| --- | --- | --- |
| 새 항목이 올라옴 | 과제, 퀴즈, 동영상 | [새 과제] 시스템 프로그래밍 · Lab 3 · 마감 12/5(금) 23:59 |
| 마감 3일 전 | 과제, 퀴즈, 시험, 동영상 | [D-3] 데이터베이스 · 기말고사 · 12/15(화) 10:30 |
| 마감 1일 전 | 과제, 퀴즈, 시험, 동영상 | [D-1] 동영상 · 13주차 강의 · 내일 23:59까지 |
| 마감일이 바뀜 | 과제, 퀴즈 | [마감 변경] 소프트웨어개발실무 · 팀 과제 · 12/5 → 12/9 |

메시지 예시의 과제명과 날짜는 형식을 보여주기 위한 가상 값이다. 시험은 내가 직접 등록하므로 새 항목 알림을 보내지 않는다.

**발송 규칙**

- 동기화는 하루 3번(08시, 14시, 21시 KST) 돌고, 알림은 동기화가 끝날 때 보낸다.
- D-3은 남은 시간이 72시간 이하, D-1은 24시간 이하가 된 뒤 처음 도는 실행에서 한 번만 보낸다.
- 노션에서 '완료'로 바꾼 항목은 D-3, D-1을 보내지 않는다.
- 한 번 실행에서 여러 건이 생기면 메시지 하나로 묶어 보낸다.
- 동영상과 시험은 노션에 없어서 알림 기록을 다른 곳에 둔다. 저장소에 작은 JSON 파일로 커밋하는 방식을 우선 검토한다.

**카카오톡 연동 준비**

- 카카오 디벨로퍼스에 앱을 만들고 카카오 로그인을 켜고, 동의항목에서 카카오톡 메시지 전송(`talk_message`)을 설정한다.
- 내 계정으로 한 번 로그인해 리프레시 토큰을 받아 둔다. 실행할 때마다 이걸로 액세스 토큰을 새로 받는다.
- REST API용 액세스 토큰은 6시간, 리프레시 토큰은 2달 동안 유효하다. 리프레시 토큰은 만료 1달 전부터 새로 발급되므로, 응답에 새 토큰이 오면 저장된 값을 교체해야 한다.

출처: [카카오톡 메시지 REST API](https://developers.kakao.com/docs/latest/ko/kakaotalk-message/rest-api), [카카오 MCP 연결법 (토큰 유효기간)](https://wikidocs.net/461910), [카카오 데브톡 (리프레시 토큰 갱신)](https://devtalk.kakao.com/t/access-token/129628)

## 기술 스택과 실행 환경

언어는 Python으로 한다. 주 5시간 안쪽으로 3주 안에 끝내야 해서 스크립트를 가장 빨리 짤 수 있고, 같은 LMS 조회 코드를 1단계 스크립트와 2단계 MCP 서버가 함께 쓸 수 있기 때문이다.

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 언어 | Python 3.12 | 1·2단계가 LMS 조회 코드를 공유 |
| LMS 연동 | Canvas REST API를 httpx로 직접 호출 | 필요한 엔드포인트가 적어 라이브러리가 필요 없음 |
| 시험 일정 | 구글 캘린더 비공개 iCal 주소 + icalendar | OAuth 없이 주소 하나로 읽기 전용 접근 |
| 노션 연동 | Notion API를 httpx로 직접 호출(버전 2022-06-28 고정) + 노션 내부 통합(토큰) | 과제DB 하나만 공유해 권한을 좁게 유지 |
| 알림 | 카카오톡 나에게 보내기 REST API | 선택한 알림 채널 |
| 실행 | GitHub Actions cron, UTC 23·5·12시 (= KST 08·14·21시) | 무료이고 PC를 켜 둘 필요 없음 |
| 비밀값 | GitHub Secrets | LMS 토큰, 노션 토큰, 카카오 키와 리프레시 토큰, 구글 캘린더 iCal 주소 |
| MCP 서버 | 공식 MCP Python SDK 2.x(MCPServer), 로컬(stdio) 실행 | Claude 데스크톱과 Claude Code에 바로 연결 |
| 테스트 | pytest | 날짜 계산(7일 역산, D-3·D-1 판단, KST 변환) 위주 |

**2단계 MCP 툴 (초안)**

- `list_upcoming(days)`: 앞으로 N일 안에 마감인 과제·퀴즈·동영상
- `get_item(lms_id)`: 항목 상세 (설명, 제출 형식, 링크)
- `list_announcements(course, days)`: 강의별 최근 공지 (조회만)
- `sync_now()`: GitHub Actions 동기화를 즉시 실행 (시간이 남으면)

노션에 쓰는 일은 이미 연결된 노션 MCP가 맡는다. 그래서 이 서버는 LMS 조회만 담당한다.

## 미정 사항과 확인할 것

HY-ON에 로그인해야 확인할 수 있는 항목(토큰, 캘린더 피드, 동영상 기한)은 결과에 따라 데이터 설계가 바뀔 수 있다.

- [ ] HY-ON 계정 → 설정에서 새 액세스 토큰을 발급할 수 있는지
- [ ] 캘린더에 캘린더 피드(.ics) 링크가 있는지 (대안용)
- [ ] 구글 캘린더 비공개 iCal 주소 복사, 시험 일정을 고르는 규칙 확정 (예: 제목에 '시험' 포함)
- [ ] 동영상 강의 출석 기한이 API로 보이는지
- [ ] 노션 과제DB에 유형, LMS ID, 링크, 알림 기록 속성 추가
- [ ] 카카오 디벨로퍼스 앱 만들기, `talk_message` 동의, 리프레시 토큰 발급
- [ ] 동영상 알림 기록을 어디에 둘지 확정 (저장소 JSON 파일 또는 다른 방식)
- [ ] 저장소 이름과 포트폴리오 공개 시점 (토큰과 개인 정보를 정리한 뒤 공개)
